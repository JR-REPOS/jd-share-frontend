          Account & server settings

          Browser connection

          Save the app's access token on this browser to connect. Account and server fields are below.

          GitHub Pages needs your running PC’s HTTPS backend address. Only enter a backend you trust with your token. Allow this page’s origin in backend Settings.

          Account & server

          Saved privately on the backend machine between sessions. Your My.JDownloader password is not stored in browser storage or uploaded to GitHub. The .env file is plaintext protected by that machine’s permissions.

          All changes take effect after restarting the backend. If managed by Docker/systemd environment variables, keep those definitions in sync. Pages origin: https://jr-repos.github.io — only add it if using that frontend. A desktop launch requires an installed app in a standard folder and a logged-in desktop session.

          History & statistics

          Server activity is shared across browsers for the selected PC. Submitted links are recorded as accepted or uncertain; only JDownloader’s finished flag counts as a completion. Recording continues while the server runs. No older history can be reconstructed.

            Browser notifications & legacy local history

            Opt-in history keeps up to 200 completions observed while this page is open. It does not reconstruct older downloads or prove a missing file finished. Times show when completion was first observed (UTC). Filenames remain on this browser. Saving a connection token clears this history.

              Download statistics

              File types

                All-time means since recording started on this backend. Active time and speed are sampled every five seconds while the server runs; outages and shutdowns are excluded. Quickest is shown only when the full transfer was observed from zero bytes. Pre-existing finished files count once, with unknown duration.

                System logs

                Records HTTP method, route template, response status and monitor failures only. No passwords, access tokens, link URLs, request bodies or raw errors. Keeps the latest 500 entries on this server; the preference survives restart.

                Step by Step setup
                1. Run JD Share on your PC. Copy .env.example to .env, set an API token and start python app.py. Keep this PC running.
                2. Get your My.JDownloader login. Register or sign in at my.jdownloader.org. Example email: name@example.com. Use that account’s password.
                3. Connect desktop JDownloader. Open Settings → My.JDownloader in the desktop app and enter the same login. Copy the exact device name shown there, e.g. JDownloader@Home-PC. Blank selects the first device.
                4. Connect this browser. In Settings, enter the backend address (e.g. http://localhost:8787 on the same PC, or your trusted HTTPS tunnel URL from another device). Copy API_TOKEN from the backend .env into Access token, then Save connection. Pages needs HTTPS and the allowed origin https://jr-repos.github.io.
                5. Generate a token if needed. Use Generate random token. Save on backend PC, restart the backend, then save that new token in the browser connection. This token belongs to JD Share, not My.JDownloader.
                6. Set server details. Example upload folder: ./uploads on the backend. Bind host 0.0.0.0 listens on the network; 127.0.0.1 is local only. Example port: 8787. These are not your public HTTPS URL.
                7. Optional Siri Shortcut. Open Siri-Shortcut for the setup guide. A published iCloud link looks like https://www.icloud.com/shortcuts/…. No account password is needed in the Shortcut.
                8. Save, restart, test. Save account/server details, restart JD Share, reopen Settings and use Test connection. Check backend, account and selected PC results separately.
